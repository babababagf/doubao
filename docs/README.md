## 状态标识

- `已确认`：用户已经明确决定，开发必须遵守。
- `推荐`：当前建议方案，低风险原型可采用，涉及真实账号、费用、生产数据前仍需确认。
- `待确认`：存在明显取舍，禁止自行决定后进入真实实现。
- `V1不做`：当前版本明确排除，不得顺手加入。

## 维护规则

1. 需求改变时先修改总纲，再同步专项文档。
2. 代码、原型、Mock 与文档不一致时，以用户最新决定和总纲为准。
3. 一个业务规则只设一个主要归属文档，其他文档使用链接，避免多处独立定义。
4. 任何影响账号、Cookie、API 密钥、费用、域名、发布和数据删除的默认行为都必须显式记录。
5. 正式编码前，所有会阻塞阶段 1 的待确认项必须关闭或设置仅限 Mock 的临时值。
