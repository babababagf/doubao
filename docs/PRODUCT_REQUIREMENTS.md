# 产品需求规格

> 版本：V0.8  
> 状态：开发前需求基线  
> 上级文档：[项目计划总纲](../PROJECT_MASTER_PLAN.md)

## 1. 产品目标

本产品只解决豆包 GEO 获客闭环，不建设通用营销平台：

```text
企业信息库（文章资料）
→ 关键词与问题词
→ DeepSeek 内容生成
→ 企业网站沉淀
→ 头条/抖音图文发布
→ 豆包 API 问题检测
→ 名称命中统计
```

V1 的判断标准不是功能数量，而是普通商户能够完整走通以上链路，并且每一步都有真实状态和可追溯结果。

## 2. 产品端划分

### 2.1 网页客户端

面向普通商户，负责资料、内容、网站、检测、发布任务和数据查看。不能包含贴牌、代理开通和平台运维功能。

### 2.2 EXE 发布助手

面向普通商户本机，负责头条、抖音扫码登录、本地会话、加密备份恢复、任务执行、人工验证和结果回传。不能承担企业资料、文章编辑和租户管理功能。

媒体账号首次连接时，用户只负责完成平台二维码/验证码等平台要求；EXE 必须先无跳转观察登录页，确认登录提示消失后自动跳转发布页做强验证，并在验证成功后立即上传加密会话备份。无法确认或超过等待时间时才显示“重新校验”作为兜底，不能把普通扫码完成流程设计成需要用户再点一次保存 Cookie。

### 2.3 总后台

平台专用独立应用和登录入口，只允许总后台角色登录，负责贴牌开通、账号、额度、期限、品牌、四类域名、全局任务运维和审计。不能查看、导出或解密媒体平台会话。

### 2.4 贴牌/代理管理端

贴牌和代理共用一个独立管理应用、域名入口和登录页。登录成功后由服务端返回角色与权限，界面展示对应菜单；贴牌管理代理、商户及本贴牌资源，代理只能管理自己创建的普通商户。不能查看、导出或解密媒体平台会话。

### 2.5 企业公开网站

面向访客和搜索/AI抓取程序，由静态生成器发布。它不是网页客户端页面，不能依赖网页客户端运行时加载正文。

### 2.6 入口与会话隔离

- 普通商户网页客户端、总后台、贴牌/代理管理端分别使用独立入口、构建产物、认证受众和 Cookie 名称。
- 贴牌与代理只在贴牌/代理管理端内共用入口和会话机制，不另建两个后台域名。
- 菜单隐藏不是权限控制；所有路由和数据接口都必须在服务端校验角色、租户和数据归属。
- 任一网页应用的登录态不得直接用于另外两个网页应用。

| 到期时间 | 是 | 不得晚于创建者自身到期时间 |

### PR-ACCOUNT-04 席位、额度与域名约束

- “可开用户数”统一指普通商户席位。贴牌总席位覆盖直属商户和全部代理下商户；分给代理时先从贴牌余额预留，不能重复销售。
- 未明确关闭的代理或商户继续占用席位；到期和停用不自动返还，明确关闭后才返还。
- 创建账号、校验上级余额、预留可开数量/算力点数/写作篇数及写入账本必须在同一事务中完成，并防止重复提交。
- 算力点数采用“预占 → 成功确认 / 失败退回”；AI 拓展成功新增 1 个去重结果词扣 1 点；AI 文章成功生成并进入文章列表 1 篇扣 30 点及 1 篇写作额度。
- 重复词、未入库结果、生成失败、取消、手动添加关键词/问题词/文章均不扣点或写作篇数；任务重试不得重复扣减。
- 发布不设置篇数额度，只受并发、频率、重复任务和平台风控保护。
- 各级主域名留空时按继承链解析。填写自定义域名只创建待验证申请，必须完成唯一性、DNS 所有权和 HTTPS 证书验证后才可启用。
- 代理主域名只用于其下属商户内容站分发，不改变管理端品牌、入口、AI 或存储继承；代理不能直接启用未验证域名。

### PR-ACCOUNT-05 密码处理

密码只在创建表单中输入；提交后使用抗暴力破解的密码哈希保存，后台列表、详情、日志和导出均不得返回原密码。登录接口必须执行失败限流、短时锁定和安全审计。该 6～12 位纯字母数字规则按产品要求采用，但应在上线风险清单中标记其口令空间有限。

## 4. 网页客户端信息架构

### PR-BRAND-01 左上角品牌

网页客户端和贴牌/代理管理端左上角都显示系统昵称与 Logo。只有总后台可以为贴牌设置或修改品牌；贴牌和代理只能复用所属贴牌配置；普通商户沿归属链继承最终所属贴牌。贴牌、代理和商户端不能出现品牌修改入口，其直接调用修改接口也必须被服务端拒绝。

### PR-BRAND-02 默认与刷新

贴牌未配置昵称或 Logo 时使用平台默认品牌。品牌配置保存一个版本号，修改成功后相关页面在重新加载或会话刷新时获取新版本，不能在各页面内写死或分别维护。

### PR-BRAND-03 企业站品牌隔离

企业公开网站的公司名称与 Logo 来自普通商户的企业资料，不使用 SaaS 左上角品牌；两者是不同用途的数据。

V1 导航固定为：

1. 控制台。
2. 企业资料。
3. 关键词与问题。
4. 企业信息库。
5. 企业图库。
6. 创作指令。
7. AI 文章创作。
8. 文章列表。
9. 企业网站。
10. 豆包检测（只读结果）。
11. 媒体账号。
12. 发布任务。

不增加独立“AI工具箱”“积分商城”“城市分站”“B2B发布”等入口。

## 5. 控制台

### PR-DASH-01 账户与额度概览

控制台顶部显示：

- 账户信息：商户名称、登录账号和账号状态。
- 到期时间。
- 关键词数量：当前未删除数量 / 开户分配上限。
- 算力点数：当前可用余额，并可查看本期消耗。
- 写作篇数：已成功生成 / 开户分配上限，或等价的剩余额度。
- 文章数量：当前未删除总数，AI 与手动文章均计入。
- 发布篇数：累计成功媒体发布记录数，不作为额度；同一文章分别成功发布到头条和抖音时计为 2 条。
- 图片存储空间：当前已用容量，并显示最后校准时间；以后单独配置容量上限时再显示“已用 / 上限”。

图片空间以平台对象元数据为实时近似值，并定期与所属贴牌 OSS 校准；取不到可靠数据时显示“暂不可用”，不得显示伪造数字。

算力点数仅是内部调用配额：AI 拓展词按 1 点/成功入库词，AI 写作按 30 点/成功篇扣减。它不是现金、充值货币或第三方模型余额，实际 API 费用仍由贴牌自备密钥承担。豆包检测永不扣算力点数，也不设置次数、日额度或商户级商业限制，固定调用所属贴牌配置的豆包 API 并由贴牌承担费用。

### PR-DASH-02 四项核心效果数据

账户概览下方的效果区只显示：

- 问题总量。
- 豆包收录数。
- 电话曝光量。
- 电话点击量。

允许在豆包收录数旁显示收录率，但必须注明其按 API 回答中的企业名称命中计算，不增加综合评分。

### PR-DASH-03 业务闭环提示

显示“企业信息库（可选） → 问题词 → 文章 → 发布 → 豆包检测”进度。信息库不是基础写作的强制前置；其他进度来自真实模块状态，不使用随机百分比。

### PR-DASH-04 趋势

最多显示两张 30 天趋势图：豆包收录数变化、电话曝光/点击变化。

## 6. 网站信息

### PR-COMP-01 单套网站资料

每个商户只维护一套网站信息，直接在“企业网站”页面编辑，不提供多记录列表和新建入口。网站信息仅用于企业公开站，不作为 AI 写作资料，不会覆盖企业信息库。

### PR-COMP-02 字段

- 公司或门店全称，必填。
- 品牌简称，可多个。
- 行业、核心业务、服务范围。
- 企业简介、优势、产品服务。
- 地址、电话、微信、二维码、营业时间。
- 资质、案例、证明材料。
- Logo、门店和产品图片。

### PR-COMP-03 版本

每次保存网站信息生成版本快照，站点生成记录固定引用当次版本。修改网站信息不会改写已有文章。

## 7. 关键词与问题词

### PR-KEY-01 关键词

商户手动创建核心关键词，可启用、停用和删除。每个关键词显示问题总量、未创作数量和已检测数量。

### PR-KEY-02 问题拓展

DeepSeek 根据关键词和商户账户公司名拓展自然问句，不读取网站信息。返回结果必须结构化并基础去重；每个成功新增并保存的去重结果词扣 1 点，重复、失败、取消和未入库结果不扣点。

### PR-KEY-03 问题状态

问题状态为：启用、停用、已删除。V1 的“问题总量”统计未删除问题，包含停用问题。

### PR-KEY-04 防重复

同一商户内规范化后完全相同的问题只保留一条。相似问题可以提示，但V1不做复杂语义合并。

## 8. 创作准备

### PR-KB-01 企业信息库

商户可建立多个信息库，每个信息库独立维护信息库名称、公司名称、品牌简称、产品服务、产品特点、品牌故事、用户痛点、信任背书、客户案例和其他信息。联系方式不作为文章生成必填项。

### PR-IMG-01 企业图库

商户可创建多个图库并上传图片。图片至少保存原图、压缩图、文件类型、大小和上传时间。来源及版权责任由商户确认。

### PR-INST-01 创作指令

创作指令只有名称和内容。系统提供默认指令，商户可创建自定义指令。指令不能覆盖企业事实、合规和安全规则。

- 未选择自定义指令时，系统默认生成1000～1200字的GEO深度文章，采用“直接回答式引言→3～4个二级标题分点论述→总结展望”结构，单段尽量不超过150字，结尾不设置FAQ。
- 默认标题指令要求完整包含优化关键词、准确承接问题词搜索意图，建议20～30字、硬上限30字，以兼容同一文章直接发布到今日头条；企业名称仅在语义自然时加入。当前年份由系统动态提供，只有榜单、趋势、价格或年度变化等时效性主题才加入年份，常青内容不强制。禁止标题党、极限词、堆词、虚假排名和第三方背书。超过30字的优化关键词在调用模型前拒绝写作并提示缩短，不产生模型费用或额度扣减。
- `{训练词占位符}` 在任务快照中替换为优化关键词，`{转化词占位符}` 替换为公司全称；自定义指令也支持这两个占位符。模型不处理 `{图片链接}`，图片由系统按文章版本中的图库图片ID快照插入。
- 企业名称或简称在正文自然出现2～3次，并按默认指令融入2～3个模糊化数据支撑点；不得进一步补造成精确金额、排名、资质或可核验的具体数据。

## 9. AI 文章创作

### PR-GEN-01 新建任务字段

| 字段 | 必填 | 规则 |
|---|---:|---|
| 优化关键词 | 是 | 显示问题总量和未创作数量 |
| 企业信息库 | 否 | 不选时自动使用基础写作模式；选择一个后进入事实增强模式 |
| 企业图库 | 否 | 不选时生成无图文章；选择时只选一个 |
| 每篇配图数 | 是 | 0、1、2、3，默认0；未选图库时必须为0 |
| 文章方向 | 是 | 默认“自动混合”；也可固定为营销介绍、榜单推荐、专业科普、问题解答、选择指南、案例解读、行业趋势或本地服务 |
| 创作指令 | 是 | 默认系统指令 |
| 创作篇数 | 是 | 1～100，默认1 |

### PR-GEN-02 自动字段

任务名自动生成；问题词作为写作主题；文章分类跟随关键词；模型成功返回可入库文章后直接为可发布状态。

### PR-GEN-03 生成规则

- 一个问题生成一篇规范文章；只要商户账号已有公司名、启用关键词和可创作问题词，就能创建基础写作任务，不强制先完善企业信息库或图库。
- 未选企业信息库时使用“基础写作模式”：只输入商户账户公司名、优化关键词、问题词、文章方向和创作指令。选择信息库后使用“事实增强模式”，公司名、简称、业务和品牌信息全部以所选信息库为准。两种模式都不读取网站信息。
- “自动混合”按问题词稳定轮换八类文章方向，并把实际方向写入任务快照；失败重试继续沿用原方向。固定方向则整批任务一致。
- 营销、榜单和案例方向同样只能引用信息库中的可核验事实；没有名次、案例或效果数据时必须改为选择标准、方法解析或中性说明，禁止模型补造。
- 默认提示词要求标题自然包含所选优化关键词并准确对应问题词，不使用夸张悬念、绝对化承诺或机械堆词；系统不再依据关键词布局、标题风格或长度执行二次模型纠偏和业务质量拦截。
- 正文第一段必须直接回答问题，并出现企业全称或已配置简称；随后以清晰语义标题组织事实依据、服务说明、适用场景/选择建议和常见问题。开头无企业实体、缺少语义标题结构或正文不合规时视为生成失败。
- 默认提示词要求正文使用3～4个二级标题，但标题数量、全文字数、企业名次数和 FAQ 不再作为入库硬门。正文仍统一执行白名单 HTML 安全清洗；空标题、清洗后不足20字的正文或超过系统容量上限的返回不属于有效文章，不得入库。
- GEO 目标是提高内容被搜索与 AI 问答系统理解、抓取和引用的概率，不得向客户承诺必然收录、固定排名或必然被豆包回答。
- 默认跳过已成功创作的问题。
- 创作篇数不能超过未创作问题数。
- 未选图库时只允许0张配图；选择图库后可设0～3张，图库图片少于单篇配图数时阻止创建。无图文章可进入文章列表，但抖音图文发布前必须补齐平台要求的图片并形成新文章版本。
- 可用写作篇数不得少于计划创作篇数，可用算力点数不得少于“计划篇数 × 30”。提交后预占最大消耗，任务结束按实际成功篇数确认并退回失败部分。
- 100篇是任务上限，不代表100并发。
- 单篇失败只重试单篇。
- 任务必须保存进度、成功数、失败数和错误原因。
- 每成功一篇扣 30 点和 1 篇写作额度；失败、取消、手动文章及同一任务幂等重试不重复扣减。
- 企业网站、头条和抖音复用同一篇不可变文章快照；发布助手只做平台必要格式适配，不生成或扣费生成额外渠道版本。
- AI 只返回标题与结构化 HTML 正文。图库图片不交给模型生成 URL，也不把易失效地址硬写入正文；系统将选定图片 ID 与文章版本一起保存，文章预览、静态站和发布助手按该快照渲染或上传图文。

### PR-GEN-04 任务状态

`排队中 → 创作中 → 已完成`为正常路径；允许进入`部分失败`或由用户进入`已停止`。终态任务不能被重复消费。

## 10. 文章列表

### PR-ART-01 统一列表

AI生成和手动添加的文章进入同一列表，通过来源字段区分。文章不能因发布成功自动删除。

### PR-ART-02 手动新增

字段仅包含标题、正文、封面/正文图片、可选关联关键词和内容状态。

### PR-ART-03 编辑器

支持标题层级、段落、加粗、列表、引用、链接和图片。保存时清理脚本、危险属性和异常样式。

### PR-ART-04 内容状态

文章对商户开放的状态为：草稿、可发布、停用；待审核仅保留为历史数据兼容状态，不再作为新建或编辑选项。AI 文章成功入库后直接为可发布，手动文章默认草稿。商户认为内容不合适时可自行编辑、停用或删除，不设置人工审核流程。

### PR-ART-05 版本与发布

编辑已发布文章时创建新版本并重新生成网站页面。网站、头条、抖音发布结果分别记录，不能用单一“已发布”覆盖全部渠道状态。

## 11. 企业网站

### PR-SITE-01 单站规则

每个商户只有一个网站和一套当前模板，不创建城市或关键词分站。

### PR-SITE-02 三套模板

- 简约企业型。
- 本地门店型。
- 品牌内容型。

模板共用数据、路由、结构化数据和静态生成器。切换模板不改变域名、文章和统计数据。

### PR-SITE-03 页面

首页、服务、问题、文章、关于/联系为固定核心页面。无内容栏目不生成空页面。

### PR-SITE-04 抓取要求

主要正文直接存在于HTML；生成标题层级、canonical、sitemap.xml、robots.txt及Organization/LocalBusiness、Article、FAQPage结构化数据。

### PR-SITE-05 联系方式

所有公开网站页面从“企业网站”页面的单套网站信息读取联系方式。V1默认不提供随机在线状态和虚假客服状态。

### PR-SITE-06 四类入口域名

- 总后台访问域名：平台专用，只提供总后台登录与管理页面。
- 贴牌/代理管理端域名：贴牌和其所属代理共用，决定登录页与左上角展示的贴牌品牌。
- 普通商户网页客户端域名：普通商户独立业务入口，决定网页客户端展示的贴牌品牌。
- 企业内容站根域名：用于为普通商户分配公开网站二级域名。

四类域名按用途分别保存，不能用一个无类型字段混用。除平台专用总后台域名外，贴牌可使用平台默认域名，也可提交自有的管理端域名、商户网页客户端域名和企业内容站根域名。代理开户时可提交自己的内容站根域名，留空则继承贴牌；商户开户时可提交站点主域名，留空则按代理、贴牌、平台顺序继承根域名并分配二级域名。所有外部域名的实际绑定、解绑和切换仍由总后台在验证后执行，代理和普通商户不能直接启用。

## 12. 豆包检测

### PR-DB-01 检测

只有贴牌角色可以在贴牌/代理管理端发起检测。后台使用该贴牌选定的豆包 API 查询目标商户的问题，保存问题、回答、可核验信源、接口状态、检测时间、命中结果和命中名称。代理与普通商户无创建权限。

### PR-DB-02 简单命中

回答规范化后包含公司全称或任一简称即命中。一个回答命中多个名称仍计一次，不要求引用链接。

### PR-DB-03 当前统计

同一问题以最新一次成功检测结果作为当前状态。失败不覆盖上一次成功结果。

### PR-DB-04 展示口径

界面统一使用“豆包收录数”。该数值仅表示豆包 API 回答包含企业全称或简称的问题数，必须在详情说明中注明，不得对外宣称为豆包 App 官方索引收录量或曝光量。

### PR-DB-05 单商户与全部商户

- 单商户查询：贴牌选择一个直属或代理下普通商户，对其当前启用问题词创建检测批次。
- 全部商户查询：对当前贴牌下全部有效普通商户创建总批次，再按商户和问题拆分执行。
- 提交前显示商户数、有效问题词数和预计 API 调用次数，批量全部查询必须二次确认。
- 相同贴牌、商户、问题和检测版本的运行中任务不得重复创建；批次支持失败明细和仅重试失败项。
- 批次不设置贴牌、商户、日/月次数等商业上限。系统只通过队列安全并发、提供方限流退避和运行中重复任务幂等保护避免瞬时压垮 API；这些技术措施不减少最终可查询总次数。

### PR-DB-06 普通商户只读

普通商户只能查看自己的豆包收录数、成功检测问题数、问题明细、回答、命中名称、检测时间和失败状态，不能看到其他商户数据，也不能从网页接口发起或重试检测。

## 13. 电话统计

### PR-PHONE-01 电话曝光

联系电话组件进入访客可视区域时记录。同一访客、同一页面、同一次访问只记录一次，不使用页面PV代替。

### PR-PHONE-02 电话点击

用户实际点击拨号链接或电话联系按钮时记录。事件需防重复、限流并按天汇总。

## 14. 媒体账号与EXE发布助手

### PR-MEDIA-01 V1账号范围

每个商户可以绑定多个今日头条账号和多个抖音账号；每个媒体账号使用独立本地浏览器资料目录。一个商户同一时间只允许一台活动发布设备，但同一 Windows 电脑可以通过单个 EXE 绑定多个商户。

### PR-MEDIA-02 扫码

扫码和登录验证只在EXE及本地浏览器发生。云端保存绑定状态、脱敏账号标识、设备标识、最近验证时间，以及由平台托管密钥信封加密的可移植会话包；任何网页后台都不能取得明文。

### PR-MEDIA-03 本地凭证与跨机恢复

- 每个媒体账号在本机使用独立持久化资料目录；登录验证成功后，EXE 提取匹配该平台域名白名单的可移植会话包：Cookie 必须保留 `name/value/domain/path/expires/httpOnly/secure/sameSite` 等完整属性，并包含相关 Origin 的 LocalStorage、SessionStorage 和 IndexedDB。不能退化为只上传 `document.cookie`。
- 可移植会话包不包含完整浏览器目录、Cache、Service Worker 文件、浏览历史、下载、扩展、真实 WebAuthn 私钥、二维码临时凭证或平台账号密码。
- 会话包经 HTTPS 发送给专用服务，使用随机数据密钥进行认证加密，数据密钥再由平台托管 KMS 包装；数据库只保存密文、包装密钥、密钥版本、内容版本、校验和和审计元数据。
- 新电脑登录同一商户工作区后，可以按媒体账号恢复加密会话；恢复后必须重新访问平台发布页验证身份与发布权限，通过后才能领取任务。
- Cookie 有效期、设备指纹、IP 和平台风控由第三方控制。恢复失败、会话失效或要求设备确认时必须重新扫码，产品不得承诺永久免登录或跨机必然成功。
- 普通商户、代理、贴牌、总后台及运维界面均不得显示、搜索、下载或导出会话明文；服务端日志、错误和审计记录不得包含凭证值。

### PR-MEDIA-04 单机多商户

- EXE 采用单实例多商户工作区，不要求或鼓励多开进程。
- 每个商户使用与网页客户端相同的账号密码在 EXE 完成一次登录；密码只用于换取该商户可撤销设备令牌，不保存明文、不经网页深链传递。
- 每个商户的任务令牌、媒体账号状态、浏览器资料和执行日志相互隔离；浏览器资料目录至少包含不可猜测的商户引用与平台，不允许不同商户共享同一资料目录。
- 一个物理设备可以绑定多个商户，但每个商户只能有一个活动设备领取任务；同一商户的所有目标媒体账号按队列逐条串行执行，不同时操作多个账号；不同商户之间可以并行。

### PR-MEDIA-05 EXE 启动登录与工作区

- 未保存有效商户设备会话时，EXE 打开后必须先进入独立登录页，登录成功才展示任务、媒体账号、日志和设置。
- 仅保存一个有效商户会话时，后续启动直接进入该商户工作区；会话失效时退回登录页。
- 保存多个商户会话时，启动后展示工作区选择，并提供“添加账号”和安全退出单个工作区；普通单账号用户不显示不必要的多账号管理界面。
- 账号与密码输入框不得常驻任何业务页面。现阶段顶部登录表单只允许作为本地开发联调临时入口，正式验收前必须移除。

### PR-PUB-01 发布任务

商户在网页端多选“可发布”文章和目标平台创建发布批次，默认同时选择头条、抖音。批次包含文章版本和图片快照、目标平台、每日发布数量、时区、计划时间和幂等标识；拆分后的任务包含目标账号与批次引用。EXE领取到期任务后获得有期限的执行租约，防止重复发布。

- 头条默认每日 3 篇，抖音默认每日 3 篇，可分别手动调高；发布数量不作为商业额度。
- 去重方式必选，默认“单平台去重”：同一文章在同一平台只创建一个任务，可以分别向头条和抖音各发一次。“全平台去重”时，同一文章只要在任一平台已有任务，所有其他平台都跳过。
- 创建批次时必须选择目标媒体账号；选择某个平台时默认勾选该商户在该平台全部有效账号，用户可以取消具体账号。选中同平台多个账号时，文章按账号轮询分配，不将同一篇广播给全部账号。
- “发布数量”控制本批次从所选可发布文章库中取用的文章数量。单平台去重时数量按每个平台计算；全平台去重时数量为全部平台合计，页面必须明确显示预计任务数。
- “选择发布文章库”在 V1 指从统一文章列表中的“可发布”文章组成任务内容池，可多选具体文章；不额外创建与文章列表重复的内容实体。
- 失败和取消不通过新建任务绕过去重，必须对原任务执行可审计重试；若无法证明平台未发布，状态进入等待人工，禁止自动重试最终提交。
- 只允许文章状态为“可发布”、版本和全部图片快照完整的文章进入批次。

### PR-PUB-02 发布状态

状态为：计划中、待执行、已领取/执行中、等待人工、成功、失败、已取消。未到计划时间的任务不能被领取。成功必须有可核验结果；失败必须有步骤和原因。

### PR-PUB-03 风控

验证码、短信、设备确认和平台风控必须暂停并交给用户，不允许绕过。

### PR-PUB-04 全自动执行

目标流程为全自动：网页端开始任务后，通过受限深链唤起 EXE；EXE 自动同步该商户任务，读取锁定的文章和图片，打开对应商户/平台浏览器资料，填写内容、上传图片、提交最终发布并核验结果。逐篇人工点击最终发布不属于目标流程。

全自动不等于无条件点击：登录失效、验证码、短信、设备确认、内容校验失败、页面结构不匹配、未知弹窗或结果不可核验时必须停止并进入等待人工。最终提交后的网络超时或页面未知状态不得自动再次点击发布。

### PR-PUB-05 发布篇数统计

发布不设置商业篇数上限。普通商户可查看累计成功发布篇数及头条/抖音分平台数量；每条成功渠道发布结果计 1 条，同一文章在两个平台均成功时计 2 条，失败、取消和等待人工不计入。

## 15. 管理应用

### PR-ADMIN-01 总后台

总后台使用平台专用应用和独立域名，只允许总后台角色登录。通过规定表单开通贴牌，并管理全局默认配置、系统昵称/Logo、四类入口域名、总额度、租户树、系统异常和审计。域名换绑必须显示验证、证书、当前生效绑定和上一条可回退绑定。

### PR-ADMIN-02 贴牌/代理共用入口

贴牌和代理共用一个管理端应用、域名和登录页。登录成功后，后端返回当前角色、权限集合和所属贴牌，前端据此生成菜单；后端仍需逐接口鉴权。代理不能通过直接输入贴牌页面地址或调用接口取得贴牌能力。

### PR-ADMIN-03 贴牌

查看总后台设置的本贴牌系统昵称与 Logo，通过规定表单开通代理并通过统一表单创建普通商户，管理代理、普通商户、自有域名资料、默认网站模板、AI配置及所属额度。贴牌可选择单个商户或全部商户发起豆包 API 检测。贴牌不能修改 SaaS 品牌；可以提交域名资料和查看状态，但不能绕过总后台直接切换生效域名。

### PR-ADMIN-04 代理

只能通过统一开户表单创建普通商户、分配自身可用额度、查看自建商户汇总和检测汇总。不能创建代理、发起豆包检测、查看AI密钥、修改系统昵称/Logo或绑定贴牌级域名；可以录入商户域名申请，但不能直接启用未验证域名。

代理功能界面可以先于贴牌功能界面开发，但数据库中必须先存在最小贴牌租户及资源继承关系，代理不能成为无贴牌归属的根租户。

### PR-ADMIN-05 密钥

密钥只允许贴牌授权管理员写入、更换和测试；保存成功后，贴牌和总后台都只能查看掩码与状态。列表、详情、日志、导出及前端接口都不得返回完整值。

### PR-ADMIN-06 大模型 API 列表

贴牌后台增加“大模型 API”菜单，支持列表、新增、编辑、测试、启用、停用和删除。新增/编辑表单包含：

- 自定义别名。
- 用途：问题拓展/文章写作、豆包检测，或两者兼用。
- 大模型平台：DeepSeek 官方、火山方舟、自定义 OpenAI 兼容接口。
- 请求接口地址。
- API Key。
- 模型名称或模型 ID。
- API 协议：Chat Completions 或 Responses API。
- 联网搜索能力及状态。

一个贴牌可以保存多条配置，但每种用途只能选择一条当前生效配置。平台配置失效时不自动切换到平台或其他贴牌密钥。

### PR-ADMIN-07 模型测试

- 写作用途测试必须验证鉴权、模型存在、结构化文本输出和基本超时。
- 豆包检测用途测试必须验证 Responses API、Web Search、回答文本和信源字段。
- 测试结果只保存时间、耗时、状态和脱敏错误，不保存或回显完整密钥。
- 自定义接口仅允许 HTTPS，并由服务端拦截内网、回环、云元数据地址及危险重定向。

### PR-ADMIN-08 云存储配置

贴牌后台增加“云存储配置”菜单。V1 先支持阿里云 OSS，字段包括：

- AccessKey ID、AccessKey Secret。
- Region/Endpoint、Bucket。
- 对象路径前缀。
- OSS 默认域名、公开自定义域名或 CDN 域名。
- 启用状态、最近测试时间和脱敏测试结果。

配置只用于企业 Logo/二维码、图库、文章配图和企业网站静态文件。数据库、任务日志、AI回答、Cookie和EXE安装包仍由平台按各自规则管理。

### PR-ADMIN-09 云存储继承和测试

- 贴牌直属商户、所属代理及代理创建的商户统一使用最终所属贴牌的存储配置。
- 代理和商户不能添加、修改或读取存储配置。
- 客户端向平台申请短时上传授权后直接上传到贴牌存储，永久 AccessKey 不下发。
- 测试连接至少验证 Bucket、目标前缀的写入/读取/删除临时对象和公开/CDN域名访问；测试对象必须使用固定隔离前缀并自动清理。
- 存储配置切换前必须验证新配置并明确迁移历史对象；失败时保留上一条有效配置和上一版网站。

### PR-ADMIN-10 资源与服务器责任

- 平台提供 SaaS 服务器、数据库、队列、管理系统、任务编排和静态网站生成服务。
- 贴牌提供并支付大模型 API、对象存储容量、外网流量和 CDN。
- 贴牌直属商户、所属代理及代理创建的商户都通过平台 API 使用最终所属贴牌资源。
- 代理和商户端不得获得大模型或存储永久密钥；平台后端负责解析租户、签名短时上传授权并执行第三方调用。
- “平台不承担算力”只指不承担第三方模型推理费用，不表示平台服务器、数据库和任务队列没有成本。

## 16. V1不做

- 城市或关键词分站。
- 多网站、拖拽建站和第四套模板。
- 其他AI平台矩阵和其他媒体群发。
- B2B、短视频生成、CRM、支付、发票和商城。
- 验证码破解、完整浏览器资料迁移、明文 Cookie 导入导出和绕过平台设备风控。
- 虚假在线状态、AI来源猜测和无法说明的数据评分。

## 17. 验收总原则

- 每个展示数字可追溯到明确数据来源。
- 每个异步任务有状态、进度、失败原因和幂等控制。
- 每个角色的越权请求由服务端拒绝。
- 每次真实媒体发布可追溯到文章版本、设备、账号状态和结果。
- Mock只验证交互，不能作为真实功能完成证据。
- 完整验收标准见[交付与质量门](DELIVERY_AND_QUALITY_GATES.md)。

## 18. 2026-08-08 实现检查点

- 发布助手正常流程固定为全自动：轮询领取、账号级会话恢复、图片下载、平台上传、内容填写、关闭已知非风险提示、最终提交、官方结果链接回传。手工成功链接不再作为正常产品流程。
- 同一商户的媒体账号从服务端同步到新电脑；每个账号的会话包独立保存和恢复。会话包覆盖完整 Cookie 属性、LocalStorage、SessionStorage 和必要 IndexedDB，不包含二维码、平台账号密码、浏览历史、缓存、下载、扩展或完整浏览器目录。
- 会话包必须由平台独立托管密钥信封加密，贴牌、代理、商户和普通后台均不可读取明文。恢复接口仅允许当前商户的发布助手设备访问，并记录不含凭据值的审计摘要。
- 本地接口和跨设备伪会话集成已通过；真实平台最终提交、真实跨电脑恢复和设备风控失败回退仍是交付前强制质量门，未通过前不得宣传“已完成全自动代运营发布”。

## 19. AI 创作任务恢复与停止口径

- 创作页必须自动展示排队、运行、完成、部分失败、失败和已停止状态，以及完成数、总数和失败原因；仅在存在活动任务时轮询，页面卸载后停止请求。
- 停止只能回收尚未成功部分的预占。与 Worker 同时结算时，以数据库锁定后的最新完成数为准；已成功文章及其 30 点算力、1 篇写作额度不回退。
- 停止后 Worker 不得继续写入文章、问题词或额度账本，也不得覆盖 `STOPPED` 终态。重复停止必须返回同一终态且不重复释放额度或写审计。
- 重试必须创建新任务并保存来源任务 ID，只选择仍启用、未删除且尚无文章的问题词；成功过的问题词不得因原任务或重试任务重复生成。

## 20. 图片空间展示口径

- “图片空间”可用性按普通商户最终所属贴牌的对象存储配置计算；只有已启用且最近连接测试成功时显示可用。
- 已用空间按商户已完成校验并进入图库的对象字节累计，删除对象成功后扣减；不得显示贴牌 Bucket 总容量、估算剩余量或虚假套餐上限。
- 配置停用、测试失败或商户缺少贴牌归属时显示“不可用”；不能因此隐藏历史已用字节，也不能向代理或商户返回 AccessKey、Bucket 配置详情。

## 21. 发布异常恢复口径

- 任务进入“需人工处理”时必须同时保存结构化原因和面向用户的文案，不允许通过文案模糊匹配决定重试。
- 只有最终提交尚未发生且原因为登录失效或验证码的任务可原任务续发。用户只需在已打开的平台窗口完成登录或安全验证；目标账号强验证成功后，EXE 必须自动恢复同账号、同平台的任务，不得再要求点击“继续发布”。
- 页面结构变化、填写校验失败、素材缺失、内容无效和平台明确拒绝均不是普通用户可安全修复的续发原因；必须保留异常证据并交由人工或研发处理，不能通过续发接口强行重发。
- 最终提交后的验证码、断网、超时或链接缺失统一归类为“提交结果不明”，禁止自动续发。平台明确拒绝、租约过期、无效内容和不完整快照也禁止原任务续发。
- 文章或配图问题必须修改文章并新建任务，因为旧任务引用不可变版本快照；不能在续发时暗中替换内容或图片。
- 续发只能通过服务端原子状态迁移完成，真实尝试次数在重新领取时增加并写审计；网页端只读显示状态，EXE 在账号验证成功后自动触发迁移。
- 对“提交结果不明”“租约过期”和历史“人工确认”任务，EXE 可提供独立的“人工核验已发布”操作。操作者必须先在平台作品列表确认已发布，并提交同平台、无查询参数的 HTTPS 官方公开作品链接。
- 人工核验成功必须原子转为 `SUCCEEDED`、保存公开链接并写独立审计；相同链接的网络重试应幂等。该操作不点击平台发布、不恢复原任务，也不得用于素材缺失、内容无效或平台明确拒绝。
- V1 暂不提供“确认未发布后重发”。无法证明未发布时继续保持阻断，避免一键解锁造成重复发布。

## 22. 计划任务到期规则

- 超过单平台每日发布数量的任务保存为 `SCHEDULED`，`scheduledAt` 使用批次时区计算后的绝对时间。未到期任务不向 EXE 队列返回，也不允许通过指定 ID 提前领取。
- EXE 的周期同步触发服务端到期检查。服务端仅将已到期、仍为 `SCHEDULED` 且文章版本快照存在的任务幂等改为 `QUEUED`，不依赖网页端持续打开。
- 本地阶段不新增独立常驻调度器，减少资源占用。未来服务器多实例部署时可换为数据库锁或队列调度，但状态迁移条件不得改变。
