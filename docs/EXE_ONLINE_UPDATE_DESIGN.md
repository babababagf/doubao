# EXE 在线更新设计（V1）

## 1. 目标与边界

发布助手采用 `electron-updater` 的 Windows NSIS 标准更新链路，不自建下载器，不执行任意 URL 返回的程序。

- 更新源归平台统一管理，不授权贴牌、代理或普通商户配置。
- 本地开发阶段不联网检查、不下载、不安装更新。
- 正式更新必须使用 HTTPS、Windows 代码签名和可验证的发布清单。
- 在线更新模块本身不读取、携带或迁移 Cookie、浏览器资料、二维码、账号密码或本地调试日志；媒体会话跨机备份由独立的加密会话接口负责，与安装包更新链路隔离。

## 2. 发布物与更新源

每次正式 Windows 发布至少上传以下同版本文件到平台更新根域名：

- `豆包获客发布助手-<version>-win-x64.exe`：NSIS 完整安装包。
- `豆包获客发布助手-<version>-win-x64.exe.blockmap`：差分下载索引。
- `latest.yml`：由 `electron-builder` 生成，包含版本、文件名、SHA-512、大小和发布时间。
- 发布说明与人工记录：SHA-256、文件大小、最低 API 版本、兼容性、灰度范围、已知问题与回退版本。

更新源必须为总后台配置的固定 HTTPS 域名，例如 `https://updates.platform-domain.example/publisher/win/`。当前客户端拒绝 HTTP、IP 地址、`localhost`、`.local`、带凭据的 URL 和前端传入的下载地址；正式发布源还必须由平台控制 TLS 证书、CDN 重定向和 `latest.yml` 中的文件地址，不能转向第三方 Host。

## 3. 客户端更新状态

客户端设置页只显示以下安全状态，不展示下载 URL 或签名细节：

| 状态 | 含义 | 用户操作 |
|---|---|---|
| 未配置 | 本地开发或后端未下发更新源 | 不检查更新 |
| 检查中 | 正在读取可信更新清单 | 等待 |
| 已是最新 | 当前版本满足策略 | 无 |
| 可更新 | 有可安装的新版本 | 查看说明后下载 |
| 下载中 | 下载完整包或差分包 | 可取消 |
| 待重启安装 | 哈希与签名验证通过 | 用户确认重启安装 |
| 被策略阻止 | 版本过低、签名异常、源不可信或不在灰度范围 | 提示联系管理员 |
| 更新失败 | 网络、清单或安装失败 | 显示脱敏错误和重试时间 |

默认策略：`autoDownload=false`、`autoInstallOnAppQuit=false`。更新下载和安装均需用户明确操作；正在执行的发布任务、等待人工验证码或本地浏览器打开时，不允许安装更新。

## 4. 后端与权限

EXE 在设备绑定鉴权后请求 `GET /api/publisher/update-policy`。总后台通过 `GET/PUT /api/super/publisher-update-policy` 保存策略，后端只返回：

- 是否允许当前设备/版本检查。
- 平台受信更新根地址标识。
- 最低支持版本、灰度批次、强制升级原因和发布时间。

最低支持版本当前只接受 `x.y.z`；客户端会阻断低于该版本的候选更新包，若本机版本已低于要求但更新源没有提供合规包，也会明确显示为阻断状态。

贴牌、代理、普通商户均不能修改更新源；总后台变更更新源、发布版本、灰度范围和最低版本均写入审计日志。商户端只显示是否可更新和发布说明。

## 5. 验证与回退

1. CI 或本地受控发布先完成 Lint、类型检查、测试、Windows 打包和 SHA-256 记录。
2. 使用干净 Windows 虚拟机验证安装、启动、检查更新、下载、重启安装与原有本地状态保留。
3. 先灰度给内部测试设备，再扩大到指定贴牌，最后全量。
4. 每个版本至少保留一个已验证的上一稳定安装包和其哈希；发现严重问题时停止在 `latest.yml` 中推荐该版本，并由总后台策略阻止继续分发。
5. NSIS 更新不能承诺所有失败场景自动回滚；安装失败时必须保留旧版本可启动或提供已验证的上一稳定安装包，不能静默覆盖。

## 6. 当前实现状态

已接入 `electron-updater` 的受控代码链路、总后台唯一更新策略和 EXE 设置页状态：默认策略禁用，EXE 仅在用户点击后检查，`autoDownload=false`、`autoInstallOnAppQuit=false`；开发包会直接阻断检查，已下载包只有在无打开本地浏览器会话、无执行中任务、无待人工处理任务时才可由用户确认重启安装。

尚未配置真实 HTTPS 更新源、Windows 代码签名、正式 `latest.yml`、灰度和回退包；当前仅有本地未签名 NSIS 开发安装包，更新检查仍会因策略缺少正式更新源而阻断。因此不得宣传为已可在线更新。
